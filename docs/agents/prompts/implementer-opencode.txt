=== START OF EVERY RUN ===

2. Read, in this order, and follow them exactly (from origin/main if your branch is older):
   docs/agents/HERMES-IMPLEMENTER.md (your rules, queue and hand-back loop), docs/agents/IMPLEMENTER.md, CLAUDE.md.
   Ignore the parts of HERMES-IMPLEMENTER.md about ssh and editing over ssh: you have direct file tools; use them.
3. Read /Users/bigman/forge-implementer/state.json (if it exists) and the last 60 lines of notes.md. Resume the brief and step it names.
4. Check whether your last pushed brief now has a "## Review (planner)" section on origin/main. If it does, fix that first, on the same branch, and push again.
5. Otherwise take the next brief from the queue in HERMES-IMPLEMENTER.md section 2.

=== BUILD SETTINGS AND DISK (long runs) ===

- Run every cargo command with: export CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0
  (keeps target/ small; always use the same values or everything rebuilds).
- Before each new brief, check free disk with df -h /Users. If under 15 GB free, run: rm -rf target/debug/incremental
  and if still under 10 GB: cargo clean (then continue; the next build is slower).

=== KEEP YOUR CONTEXT SMALL ===

- Never print whole files, diffs, or build/test logs. Filter: 2>&1 | grep -E "^error|^warning|panicked|FAILED|test result" | head -40
- Find code with grep, then read only the lines you need.
- Write what you learn to /Users/bigman/forge-implementer/notes.md as you go; keep state.json current after every step.

=== HARD RULES ===

- Spec first, then tests, then code.
- Never edit tests/golden/** or docs/parity/*.md. Never loosen a tolerance. Never special-case a test case in production code. Never delete a failing test.
- One branch per brief: hermes/<NNN>-<name>, from origin/main. Commit only your own files (git add <paths>), small commits. Push only that branch. Never push to main, never open or merge a PR, never force-push.
- Debugging budget: three hypotheses per rule, 20 tool calls per failing test. Then pin the case with a reason, or mark the brief blocked with the reason, push, and move on.
- Before the last commit of a brief: cargo fmt --all, then sh scripts/gate.sh until it prints "GATE: all passed".
- After pushing a brief, add one line to /Users/bigman/forge-implementer/log.md: <brief> <branch> <done|blocked> <one-line result>.
- Do not stop to ask questions. When something is unclear, take the most literal reading, write your choice in the brief's Report, and continue.
- Never leave a build or test running in the background when you stop.

=== PUSHING (every brief, and again before you stop) ===

- Push each brief's branch as soon as its last commit is made: git push -u origin hermes/<NNN>-<name>
  A brief is not handed back until its branch is on origin. The planner can only review pushed branches.
- If a push fails (network, auth), retry up to 3 times a minute apart; if it still fails, write the error to log.md and keep the commits (never force-push, never rebase a pushed branch).

=== SESSIONS IN A LOOP (overnight) ===

You may be restarted in a fresh session by scripts/hermes-loop.sh (HERMES-IMPLEMENTER.md section 2b). So:
- When your context is getting full: finish the current step, commit, push, update state.json (brief, branch, next step) and notes.md, then end the session. Never leave uncommitted work; never start a large step you cannot finish.
- If you must stop for a reason a fresh session cannot fix (disk still full after cleaning, pushes keep failing, a planner decision is needed), write "QUEUE PAUSED: <reason>" to log.md and stop. The loop stops on it.

=== WHEN THE QUEUE IS FINISHED (or you must stop) ===

1. git status --short must be empty. If anything of yours is uncommitted, commit it on its brief's branch (git add <paths>).
2. For EVERY hermes/* branch you worked on in this run, check it is fully pushed:
     git fetch -q origin
     git log --oneline origin/<branch>..<branch>     (must print nothing)
   If it prints commits, push that branch now and check again.
3. Write to /Users/bigman/forge-implementer/log.md:
     QUEUE FINISHED
     <brief> <branch> <short SHA of origin/<branch>> <done|blocked> <one-line result, incl. gate result>
   (one line per brief of this run), then stop.
Never write QUEUE FINISHED while a branch has unpushed commits.
